## 2024-04-09 - Scroll Event Performance Pattern
**Learning:** The `Navbar` and `StickyBooking` components were using naive scroll event listeners `window.addEventListener('scroll', handleScroll)`, which triggered React state updates and potentially DOM queries (`document.getElementById`) on every single scroll pixel change. This is a common performance anti-pattern that can lead to excessive re-renders and layout thrashing, especially in a Next.js App Router application where smooth scrolling (e.g., via Lenis) is heavily used.
**Action:** When implementing scroll listeners, always wrap the state updates and expensive DOM operations in a `requestAnimationFrame` callback to throttle execution to the browser's paint cycle. Ensure the listener is registered with `{ passive: true }` to prevent blocking the main thread, and always clean up by calling `cancelAnimationFrame` inside the `useEffect` cleanup function to prevent memory leaks and unmounted component state updates.
